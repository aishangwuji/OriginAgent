# OriginAgent 连续性与记忆操作系统架构提纲

Date: 2026-06-08
Status: Proposed
Scope: OriginAgent 长期连续交互、记忆作用域治理、工作记忆、检索融合与上下文构造的独立架构提纲

## 1. 文档目标

本提纲用于定义 OriginAgent 的“连续性与记忆操作系统”主线，为后续 Phase 1 及之后的实现提供设计边界。

它回答的问题不是“如何保存更多历史”，而是：

1. 一次推理到底应该看到哪些上下文。
2. 这些上下文属于谁、来自哪里、是否可信。
3. 哪些信息只应停留在短期工作记忆。
4. 哪些信息应晋升为长期记忆。
5. 哪些信息应该遗忘、过期或降权。

## 2. 为什么需要单独建模

如果没有这条主线，系统会持续滑向两种低质量模式：

1. 靠最近对话硬撑连续性。
2. 靠把长期记忆粗暴拼进 prompt 模拟连续性。

这两种方式在短对话里可以工作，但一旦进入长期运行、跨端切换、分层感知、世界模型和物理动作阶段，就会出现：

1. 记忆污染。
2. 跨会话归属不清。
3. 召回噪声过高。
4. 上下文预算失控。
5. 新旧知识冲突无法稳定治理。

因此，连续性必须作为独立的基础能力建模。

## 3. 设计目标

这条主线的目标不是追求“永不忘记”，而是追求：

1. 长期连续但不过载。
2. 会话切换尽量无感但不混乱。
3. 作用域清晰，避免跨角色污染。
4. 上下文组装可解释、可调试、可审计。
5. 感知、世界模型、认知循环和动作层都能复用同一套上下文治理机制。

## 4. 非目标

本提纲不直接解决以下问题：

1. 多模态底层模型训练。
2. 世界模型本体设计细节。
3. 设备动作协议。
4. 完整向量数据库选型定稿。

这些问题会和本主线发生交互，但不在本提纲内展开。

## 5. 核心设计判断

### 5.1 不是双上下文，而是四层运行视图

最小可靠结构应至少包含四层：

1. 对话视图：最近多轮原始消息，负责连贯性、指代、省略理解。
2. 检索视图：从长期记忆或索引层召回的知识片段。
3. 工作视图：当前任务、当前计划、当前待确认项、当前工具结果。
4. 世界视图：当前环境状态和外部世界摘要。

LLM 每轮真正接收的是这四层视图经组装后的结果，而不是原始存储本身。

### 5.2 连续性交互不是“会话全合并”

长期连续不等于把所有会话短期记忆打通。默认情况下：

1. 短期工作记忆应隔离。
2. 长期记忆应按作用域召回。
3. 跨会话连续性主要由身份层、作用域层和检索层提供。

### 5.3 记忆操作系统必须先于感知扩张稳定

一旦接入感知和世界模型，就必须回答：

1. 这条快照归属于谁。
2. 这条状态属于哪个房间、设备、会话或任务。
3. 它是否能被其他上下文复用。

因此，这条主线最晚必须在 Phase 2 前半段前具备最小可用骨架。

## 6. 架构总览

```text
User / Device / Household
         ↓
Identity Layer
         ↓
Scope Resolver
         ↓
Memory Sources
  ├─ dialogue history
  ├─ working memory
  ├─ facts
  ├─ nearline memory
  ├─ world model
  └─ retrieval indexes
         ↓
Retrieval Fusion
         ↓
Context Assembler
         ↓
LLM-facing message bundle
         ↓
Promotion / Forgetting / Conflict Resolver
```

## 7. 模块划分

### 7.1 Identity Layer

职责：

1. 引入稳定的 `user_id`。
2. 建模 `household_id`、`device_id`、`session_id`、`task_id` 关系。
3. 为后续记忆归属、感知归属和动作归属提供基础标识。

最小版本建议：

1. `user_id`
2. `session_id`
3. `device_id`

后续扩展：

1. `household_id`
2. `actor_id`
3. `room_id`

### 7.2 Scope Model

职责：

定义记忆和状态的可见范围。

建议作用域级别：

1. `global`
2. `household`
3. `user`
4. `device`
5. `session`
6. `task`

默认规则：

1. 短期工作记忆默认 `session` 或 `task` 级别。
2. 用户偏好默认 `user` 级别。
3. 环境常识默认 `household` 或 `device` 级别。
4. 高敏感信息默认不跨更宽作用域自动传播。

### 7.3 Working Memory

职责：

承载当前回合之前的“当前工作集”，而不是仅靠最近对话消息。

最小内容建议：

1. 当前目标
2. 当前计划
3. 当前待确认项
4. 当前高优先级事实
5. 当前世界关注点
6. 当前工具执行残留结果

工作记忆应具备：

1. 显式更新机制
2. 过期机制
3. 冲突检测

### 7.4 Retrieval Fusion

职责：

融合多个来源的召回结果，而不是单一依赖某一种搜索。

建议融合来源：

1. 会话历史全文检索
2. 长期事实检索
3. 向量检索
4. nearline memory 检索
5. 世界模型查询

最小策略：

1. 先按来源召回
2. 再按相关性、时效性、作用域、置信度排序
3. 再限预算裁剪

### 7.5 Context Assembler

职责：

将四层运行视图和系统提示拼成最终发给 LLM 的消息包。

它至少应负责：

1. token 预算分配
2. 来源排序
3. 去重
4. 冲突标注
5. 上下文分段组织

建议输出结构：

1. system prompt
2. runtime state block
3. working memory block
4. retrieved context block
5. world state block
6. recent dialogue messages
7. current user message

### 7.6 Promotion / Forgetting / Conflict Resolver

职责：

决定信息如何在不同层之间流动。

最小要回答的问题：

1. 什么时候从工作记忆晋升到长期记忆。
2. 什么时候仅保留摘要。
3. 什么时候降权或遗忘。
4. 新旧知识冲突时怎么办。

建议初始机制：

1. 时间衰减
2. 访问频次衰减
3. 置信度阈值
4. 显式待确认状态

## 8. 四层运行视图详解

### 8.1 对话视图

保留最近 N 轮真实对话，解决：

1. 指代
2. 省略
3. 语气连续性
4. 本轮局部上下文

### 8.2 检索视图

只放“当前问题相关”的召回片段，不放整片历史。

它负责：

1. 跨时间连续性
2. 跨会话连续性
3. 隐性背景补全

### 8.3 工作视图

工作视图是上下文质量的关键，因为它决定 Agent 当前“正在做什么”。

如果没有它，系统会不断重复从对话和长期记忆中反推当前任务，成本高且容易漂移。

### 8.4 世界视图

世界视图用于承载当前环境状态，不应简单塞到长期事实里。

它负责：

1. 当前场景状态
2. 感知异常
3. 设备或空间上下文
4. 与当前任务有关的环境约束

## 9. 与现有 OriginAgent 的衔接建议

### 9.1 可复用部分

1. `SessionManager`
2. `ContextBuilder`
3. `FactStore`
4. `NearlineMemoryPipeline`
5. `Dream`
6. `SessionSearchIndexService`

### 9.2 需要增强或新增的部分

1. `IdentityResolver`
2. `ScopeResolver`
3. `WorkingMemoryManager`
4. `RetrievalFusion`
5. `ContextAssembler` v2
6. `ForgettingPolicy`
7. `RoamingPrewarmService`

## 10. 分阶段落点建议

### Phase 0

完成本提纲并冻结边界。

### Phase 1

实现最小骨架：

1. 身份层最小模型
2. 作用域模型最小版
3. 工作记忆最小版
4. `ContextAssembler` v2 最小版

### Phase 2

让视觉快照和世界摘要通过该主线进入上下文构造。

### Phase 3

扩展：

1. 检索融合
2. 晋升策略
3. 遗忘策略
4. 最小预热能力

### Phase 4

让动作层消费这套连续性基础设施。

### Phase 5

收口：

1. 会话漫游体验
2. 长期记忆膨胀治理
3. 上下文构造质量指标

## 11. 第一批建议任务

1. `RQ-002` 连续性与记忆操作系统边界定义。
2. `RQ-003` 身份层与作用域模型设计。
3. `RQ-004` 工作记忆与 `ContextAssembler` v2 最小方案。
4. `RQ-013` 检索融合最小方案设计。
5. `RQ-014` 晋升与遗忘策略最小方案设计。

## 12. 当前建议的下一步

最合适的下一步不是直接实现完整系统，而是：

1. 先把 `RQ-002`、`RQ-003`、`RQ-004` 拆成正式任务包。
2. 先做最小骨架，不追求一步到位。
3. 在 Phase 1 内证明：上下文构造已经不再只是“最近对话 + 静态记忆拼接”。

这条主线一旦站稳，后续感知、世界模型和动作层都会少很多返工。
